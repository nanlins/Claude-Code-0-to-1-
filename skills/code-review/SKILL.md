# 代码审查

按以下流程审查代码：

1. **理解范围**：用 `list_files` / `git status` 列出变更文件，逐个阅读。
2. **检查正确性**：off-by-one 错误、空值处理、async/await 误用、竞态条件。
3. **检查安全**：路径穿越、命令注入、代码中的密钥、不安全的反序列化。
4. **检查风格**：与周围代码的一致性、命名、死代码。
5. **报告**：每个发现给出 `[P0|P1|P2] 文件:行号 — 问题 — 建议修复`。
   - P0：必须修复（安全问题 / 数据丢失）
   - P1：应当修复（bug / 可维护性）
   - P2：锦上添花（风格）
6. 除非被明确要求，否则审查过程中不修改任何文件。
